# v2.8.0 Notion 화면 작업 목록 (운영 워크스페이스)

- 대상: v2.7.19를 쓰는 운영 워크스페이스를 v2.8.0으로 올릴 때 **사람이 Notion·솔라피 화면에서 직접 하는 일**만 모은 체크리스트다. 칸(속성) 추가·코드 배포·운영 스캔처럼 운영 AI가 API로 하는 일은 넣지 않았다.
- 기준 문서는 [v2.8.0 지침](v2.8.0.md)이다. 이 목록의 줄은 지침 맨 위 "운영 적용 순서" 표 세 개에서 사람 단계(원장님·원본 지원 브라우저)만 뽑아 번호를 붙인 것이고, 각 줄 끝의 (표 번호 · 항목 번호)에 실제 값(수식 원문·버튼 순서·선택지)이 있다. 수식 원문은 여기에 옮겨 적지 않는다 — 지침과 둘로 나뉘어 어긋나지 않게.
- 순서: **A(미리) → [운영 AI: 1단계 칸 추가 → 2단계 코드 배포] → C → D → E → F → G**. A의 템플릿 20개가 모두 승인되기 전에는 코드를 배포하지 않는다.
- 누가: A는 원장님(솔라피 계정), C·D·F·G는 원본 지원(브라우저 도구) 또는 원장님, E는 운영 AI와 원장님이 함께.
- 운영 AI는 적용을 시작할 때 이 목록을 그 학원 Notion에 체크리스트 페이지로 옮겨 진행을 표시해도 된다. 원본은 이 파일 하나다.
- DB는 이름·역할로 적었다. 운영 DB 이름이 다르면 같은 역할의 DB에 적용한다. 원본 ID·주소·키는 쓰지 않는다. 웹훅 주소와 키는 관리자 설정 → 웹훅 체크리스트에서 복사한다.

## 공통 주의 (Notion 화면)

- 다른 DB를 거치는 수식, 버튼, 자동화, 페이지 탭은 API로 바꿀 수 없어 화면에서 고친다. 자세한 요령은 [적용 절차](../기준/적용-절차.md) 5장과 [v2.7 Notion 작업 목록](v2.7-노션-작업.md) "공통 주의"를 따른다.
- 수식을 바꾸기 전에 지금 원문을 복사해 지침 부록의 "바꾸기 전"과 대조한다. 둘 다 아니면 멈추고 원본 요청을 한다.
- 웹훅 버튼은 키가 든 기존 버튼을 속성 복제해 주소만 바꾼다(키를 손으로 옮겨 적지 않는다).
- 지우는 일은 F(정리)에만 있다. 지우기 전에 다른 수식·보기·버튼이 그 속성을 쓰는지 확인한다.
- 한 단계를 끝낼 때마다 운영 스캔으로 원본 지문과 비교해 그 단계 항목이 "같음"이 됐는지 본다.


## A. 배포 전 — 미리 (원장님)

솔라피 심사가 영업일 2~3일 걸리므로 가장 먼저 한다.

- [ ] **N-1** 솔라피에서 (구역) 템플릿 전부 심사 신청(알림톡 기준 9장 표, 10/31 시간표 변경·등록·클래스 변경 안내 포함. 원본 알림톡 설정 행 본문을 학원 이름·문의 번호·안내멘트만 바꿔서). 기존 템플릿을 고치지 않고 새로 등록한다. 승인되면 템플릿 ID를 운영 AI에 전달. **둘째 표 0단계: 템플릿 20개가 모두 승인되기 전에는 2단계 코드를 배포하지 않는다** (표1 · 항목 19·23·25)

## G. 매뉴얼 통째 교체 (운영 소유자 승인 후)

- [ ] **G-1** 운영 소유자에게 교체 승인을 받는다(운영 매뉴얼에 학원이 직접 적은 내용이 있으면 먼저 따로 보관).
- [ ] **G-2** 원본 매뉴얼 페이지 전체(하위 페이지, 부록 4주 따라하기 가이드, 그 아래 문의·요청(학원) DB 포함)를 운영 워크스페이스로 복제한다. 워크스페이스 사이 복제는 API로 되지 않아 화면에서 한다.
- [ ] **G-3** 예전 운영 매뉴얼은 지우지 않고 보관 페이지로 옮긴다. 메뉴(학원) DB의 `매뉴얼` 행이 새 매뉴얼을 가리키게 한다.
- [ ] **G-4** 본문의 학원별 값(학원 이름, 웹페이지 주소, 학교 검색·리포트 주소)을 운영 값으로 바꾼다. 원본 이름("하다 수학학원")·원본 주소가 남지 않았는지 검색한다.
